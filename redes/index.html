1. O que é um servidor web?

Um servidor web é um programa responsável por receber solicitações de navegadores e enviar respostas por meio do protocolo HTTP ou HTTPS. Essas respostas podem conter páginas HTML, arquivos CSS, JavaScript, imagens e outros recursos.

Quando você acessa um endereço como http://localhost:9000, o navegador solicita uma página ao servidor que está funcionando no próprio computador.

O Python possui um módulo chamado http.server, que permite iniciar um servidor HTTP simples sem instalar bibliotecas adicionais. Ele é útil para aprender, testar páginas e desenvolver sites localmente.

2. Verificar se o Python está instalado

Antes de iniciar o servidor, verifique se o Python 3 está disponível no sistema. O comando abaixo mostra a versão instalada. 

python3 --version

Se o Python não estiver instalado, em sistemas Ubuntu ou Debian você pode instalá-lo com os comandos: 

sudo apt update
sudo apt install python3

O comando sudo executa uma operação com privilégios administrativos. O comando apt gerencia pacotes em distribuições baseadas em Debian.

3. Criar a estrutura do site

Para organizar o projeto, crie uma pasta e os arquivos necessários. O arquivo index.html será a página principal. 

mkdir -p ~/meu-site/imagens
cd ~/meu-site 
touch index.html style.css script.js

Estrutura sugerida:

meu-site/
├── index.html 
├── style.css 
├── script.js 
└── imagens/

O HTML define o conteúdo, o CSS controla a aparência e o JavaScript adiciona interatividade. A pasta imagens pode guardar imagens utilizadas na página.

4. Como iniciar um servidor web com Python

Entre na pasta que contém o arquivo index.html e execute: 

cd ~/meu-site
python3 -m http.server 9000

O comando python3 -m http.server 9000 executa o módulo HTTP do Python e inicia o servidor na porta TCP 9000.

  • python3: executa o interpretador Python.
  • -m: executa um módulo disponível no Python.
  • http.server: fornece um servidor HTTP simples.
  • 8000: define a porta usada pelo servidor.

Para acessar o site, abra o navegador e digite:

http://localhost:9000

O endereço localhost representa o próprio computador. Para interromper o servidor, pressione Ctrl + C no terminal.

Atenção: esse servidor é destinado a testes e desenvolvimento. Não é recomendado para hospedar aplicações de produção expostas à internet.

5. O que é um endereço IP?

O endereço IP identifica uma interface em uma rede IP e permite que dispositivos encaminhem dados até o destino. Em redes locais, um computador geralmente possui um endereço privado, como 192.168.1.50.

Comandos úteis para consultar os endereços e as interfaces:

ip addr
ip -br addr 
ip link 
hostname -I
  • ip addr: mostra endereços IP e interfaces.
  • ip -br addr: apresenta um resumo mais compacto.
  • ip link: mostra as interfaces e seu estado.
  • hostname -I: mostra os endereços IP do computador.

Interfaces como eth0, enp3s0 e wlan0 podem representar conexões Ethernet ou Wi-Fi, dependendo do sistema.

6. O que é uma rota de rede?

Uma rota indica como o sistema deve encaminhar pacotes para outras redes. O gateway padrão normalmente é o roteador utilizado para alcançar destinos fora da rede local. 

ip route

Procure uma linha iniciada por default via. Ela costuma indicar o gateway padrão, quando configurado.

7. Como testar a conectividade

O comando ping envia mensagens de teste para verificar se um destino responde pela rede. 

ping -c 4 127.0.0.1
ping -c 4 8.8.8.8 
ping -c 4 google.com
  • 127.0.0.1: testa a comunicação com o próprio computador.
  • 8.8.8.8: testa um destino externo por endereço IP.
  • google.com: testa o acesso por nome de domínio.
  • -c 4: envia quatro solicitações e encerra o teste.

Se um endereço IP responder, mas o nome do domínio não, pode haver um problema de resolução DNS. Entretanto, alguns destinos bloqueiam respostas ao ping, então um teste sem resposta não comprova sozinho que a rede está fora do ar.

8. O que são portas de rede?

Portas TCP e UDP identificam pontos de comunicação utilizados pelos serviços de um computador. Um servidor web pode, por exemplo, escutar na porta TCP 9000.

Para verificar as portas e conexões:

ss -lnt
ss -lun 
ss -tunap 
ss -lnt | grep ':9000'
  • ss -lnt: lista portas TCP em estado de escuta.
  • ss -lun: lista sockets UDP.
  • ss -tunap: mostra conexões e sockets TCP/UDP.
  • grep ':9000': filtra linhas relacionadas à porta 8000.

Se o servidor estiver ativo, você deverá encontrar uma entrada relacionada à porta 8000. A opção -p pode mostrar o processo associado, dependendo das permissões.

9. Como testar a resposta HTTP

O programa curl permite enviar solicitações HTTP pelo terminal. Ele é útil para verificar se o servidor responde sem precisar abrir um navegador. 

curl -I http://localhost:8000
curl http://localhost:8000

A opção -I solicita apenas os cabeçalhos da resposta. Uma resposta HTTP 200 OK indica que a solicitação foi atendida com sucesso.

Se aparecer uma mensagem de conexão recusada, verifique se o servidor está em execução e se está escutando na porta correta.

10. O que é DNS?

O DNS traduz nomes de domínio, como google.com, em informações de endereçamento usadas para localizar serviços na rede. 

getent hosts google.com
cat /etc/resolv.conf 
resolvectl status
  • getent hosts: consulta a resolução de nomes do sistema.
  • /etc/resolv.conf: exibe a configuração de resolvedores DNS.
  • resolvectl status: mostra informações do resolvedor em sistemas compatíveis.

11. Como verificar o firewall

O firewall controla quais conexões de rede podem entrar ou sair do sistema. Regras restritivas podem impedir que outros dispositivos acessem um servidor web. 

sudo ufw status
sudo nft list ruleset

O primeiro comando verifica o estado do UFW, se estiver instalado. O segundo lista as regras do nftables. Não altere as regras sem compreender as consequências para a segurança do sistema.

12. Acessar o servidor pela rede local

Para permitir que outros dispositivos da mesma rede tentem acessar o site, você pode iniciar o servidor escutando em todas as interfaces IPv4: 

python3 -m http.server 9000 --bind 0.0.0.0

Consulte o IP do computador:

hostname -I

Se o endereço local for 192.168.1.50, por exemplo, acesse no outro dispositivo: 

http://192.168.1.50:8000

Substitua o exemplo pelo IP real. Os dois dispositivos precisam ter conectividade entre si, e o firewall não pode bloquear a conexão. Não exponha esse servidor diretamente à internet.

13. Sequência rápida de diagnóstico

Se o site não abrir, execute os comandos abaixo em sequência para investigar a interface, a rota, a porta e a resposta HTTP: 

ip -br addr
ip route 
ping -c 4 8.8.8.8 
ss -lnt | grep ':8000' 
curl -I http://localhost:8000

Analise cada resultado. Se o IP local estiver configurado, mas a porta 8000 não aparecer, confirme se o servidor foi iniciado. Se o acesso local funcionar, mas outro dispositivo não conseguir acessar, investigue o IP utilizado, a conectividade local e o firewall.
